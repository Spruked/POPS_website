## Boundaries and launch dependencies

- Local customer service: Django authentication, Argon2 password hashing, database sessions, CSRF, signed expiring verification links, one-time reset tokens, validation and persistent request throttling. No paid authentication provider.
- SQLite accounts, beta interest, support requests, sessions and email outbox reside under .local/customers. They must never be published as static files or copied to production as part of an asset bundle. Vite explicitly denies .local, the virtual environment, and backend source.
- Development email is file-based, never claimed delivered. Production activation requires a reviewed host, HTTPS, a protected secret, allowed hosts, SMTP delivery, backups/retention, request monitoring, trusted proxy configuration and a separate approval.
- Beta form records interest, not admission. First-100 benefits and qualifying purchase accounting are unapproved; no live counter or entitlement is issued.
- Checkout is informational. Local /api/checkout paths return unavailable and do not call providers. The preserved legacy backend file still contains its old dormant payment implementation; any future deployment must explicitly deny or route /api/checkout to the deferred service rather than expose that legacy endpoint.
- Installer, supported Windows versions/device limits, activation/delivery, update/maintenance scope, refund/support terms, Android entitlement and actual export capabilities require owner/release verification.
- The interactive demo adapts copied real application screens using deterministic fictional records. It is a browser demonstration rather than proof of release availability. The relationship tree is conceptual; an official installed-application recording remains a separate asset.
- Production is unchanged, including its current capabilities and deficiencies.
